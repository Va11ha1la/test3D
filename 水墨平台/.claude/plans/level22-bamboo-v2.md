# Plan: Add and redesign level 22 from docs/22_墨竹行_关卡设计.md

## Goal

Add a new level 22 by duplicating the current level 21 bamboo-scroll level, then redesign level 22 to match `docs/22_墨竹行_关卡设计.md` and the constraints in the other docs:

- `docs/策划案.md`: art/gameplay authority, one painting subject + one interaction verb, dense/sparse composition, no abstract platforms.
- `docs/movement_spec.md`: movement spacing limits and soft-wall requirements.
- `docs/reachability_report.md`: new level connection discipline and validation mindset.
- `docs/视频生成案.md`: bamboo-scroll visual language and feedback style.

Level 21 must remain the existing smaller `墨竹行`; level 22 becomes the larger v2 `墨竹行`.

## Current implementation model

- Level order lives in `scripts/src/00_state_levels_keys.lua` (`LEVELS`).
- Level 21 currently uses `trace = true, traceKey = "bamboo"`.
- `scripts/src/85_trace_levels.lua` dispatches `traceKey == "bamboo"` to `generateBambooScroll()`.
- `scripts/src/88_bamboo_scroll.lua` contains the bamboo-scroll data, collision generation, bud interaction, and drawing.
- Bundles are generated by `tools/build_main.ps1` into `scripts/main.generated.lua`; `scripts/main.lua` is kept in sync.

## Implementation approach

### 1. Add level 22 without breaking level 21

Edit `scripts/src/00_state_levels_keys.lua`:

- Keep level 21 as-is:
  - `id = "trace_bamboo_scroll"`
  - `traceKey = "bamboo"`
- Add level 22:
  - `id = "trace_bamboo_scroll_v2"`
  - `trace = true`
  - `traceKey = "bamboo_v2"`
  - `name = "墨竹行"`
  - `title = "水墨平台跳跃 - 墨竹长卷·大格局"`
  - same visual/movement palette as level 21 unless the v2 data overrides it.

### 2. Make bamboo-scroll runtime data-selectable

Edit `scripts/src/85_trace_levels.lua` and `scripts/src/88_bamboo_scroll.lua`:

- Replace the hard-coded `traceKey == "bamboo"` dispatch with a bamboo-trace selector that accepts both `bamboo` and `bamboo_v2`.
- Keep current `BAMBOO_DATA` as the level 21 data.
- Add a separate `BAMBOO_DATA_22` for the level 22 design.
- Have `generateBambooScroll()` select the active data by `currentLevel.traceKey` and store it on `TRACE_RT`, so rendering/collision use the correct data while level 21 remains unchanged.

### 3. Build level 22 gameplay data from the doc

Implement `BAMBOO_DATA_22` as a 8400 × 2600 world with:

- 7 checkpoint entries / respawn anchors.
- Ground/stones and bamboo structures matching the six/seven-moment design:
  1. 卷首坡石: safe intro, bud 1.
  2. 登篁: two chimney climbs and vertical-ladder bud 2.
  3. 云上竹海: high bamboo-top rhythm, chain buds 3-5, bridge bud 6, double-route buds 7a/7b, two hanging bamboo-tip ropes.
  4. 雾海跌落: controlled drop with chain buds 8-9 and ink-pool catch.
  5. 仙鹤雾渡: crane ferry across fog-death zone.
  6. 谷中主笔: long diagonal bamboo slope and spring-tip bud 10.
  7. 卷尾长桥: long bridge bud 11 and final scroll mouth.
- Death zones for fog abysses, while allowing non-lethal fallback layers elsewhere.
- Middle/background motifs only to the extent needed for the playable first pass; the design doc explicitly says the complete middle/background pass can wait until the foreground is approved.

### 4. Extend bud mechanics for v2

Keep existing level 21 bud behavior as the default. Add data-driven modes used only by level 22:

- `bridge` / default: existing stop-and-draw platforms.
- `ladder`: same system, but pads are vertical/zig-zag and use smaller vertical spacing.
- `chain`: dash hit launches the player without stopping on a new platform; refreshes dash and applies configured `vx/vy`.
- `spring`: dash hit draws a springy bamboo tip; standing on it and jumping applies a high upward impulse.
- `long_bridge`: slower sequential bridge growth for the finale.

Implementation will stay global-function based because the bundle is already near the Lua top-level local limit.

### 5. Reuse rope/crane systems for bamboo v2

Edit `scripts/src/40_gameplay_targets.lua` and `scripts/src/88_bamboo_scroll.lua`:

- Add a trace-bamboo special-mechanics hook called from `updateSpecialBeforeMovement()`.
- Reuse existing player state fields (`player.swingRope`, `player.ridingCrane`, `player.craneCooldown`) instead of adding parallel systems.
- For level 22:
  - Hanging bamboo tips use the same swing behavior as peach ropes, but are drawn as vertical bamboo tips/leaves.
  - The crane ferry uses the existing riding/dismount dash model, with a level-specific path rather than the generic horizontal roaming crane.

### 6. Add v2-specific collision and feedback

- Add rectangular fog death-zone checks to trace collision.
- Add ink-pool ripples / landing slowdown where the doc calls for a buffered hard landing.
- Add temporary faster vertical camera follow in the fall shaft.
- Keep existing hitstop, ink burst, rejection shake, and camera nudge behavior.

### 7. Rebuild and validate

- Run `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/build_main.ps1`.
- Sync `scripts/main.lua` from `scripts/main.generated.lua` if the generated bundle differs.
- Verify level count/order includes:
  - 21: `trace_bamboo_scroll`, `traceKey = "bamboo"`
  - 22: `trace_bamboo_scroll_v2`, `traceKey = "bamboo_v2"`
- Run lightweight Lua/text checks for the new data and generated bundle.
- Optionally launch local UrhoX runtime afterward for a smoke test.

## Notes / tradeoffs

- I will not overwrite level 21; level 22 gets its own data key.
- I will implement a playable foreground-first version, matching the design document’s own priority. Full middle/background polish can be a later visual pass after the route is approved.
- Existing `tools/reachability_check.py` currently targets the older generated-branch levels, not this trace-bamboo runtime. I will do structural spacing checks and runtime smoke testing rather than pretending that existing checker fully covers level 22.
